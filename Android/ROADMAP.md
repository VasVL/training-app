# Roadmap реализации TrainingApp

> Порядок реализации функционала. Обновлять по мере прогресса (отмечать выполненное ✅).

## Фаза 0. Фундамент
- [x] **DI (Hilt)** — `Application` класс (`@HiltAndroidApp`), `MainActivity` (`@AndroidEntryPoint`), `DatabaseModule` в `core/database` (Hilt `@Provides` для `TrainingDatabase` + DAO). Без DI ничего не заработает.
- [x] **core:common:domain** — `Resource<T>` (Loading/Success/Error).
- [x] **core:common:logging** — `LogExtensions` поверх Timber.
- [x] **core:common:ui** — общий UI-ресурс `ic_add`.
- [x] **Реализация Navigator в `app`** — `NavigatorImpl` (маппинг `Screen` → `NavDirections`), `NavigationModule` (Hilt `@Binds`), nav_graph.xml. Без этого нет навигации.
- [x] **Coil** — подключить в `app` (implementation(libs.coil)). Библиотека загрузки картинок.
- [x] **Изоляция persistence** — `domain` фичей объявляет порты (интерфейсы репозиториев), `data`-подмодули реализуют их через DAO из `core/database`. `app` не зависит от Room напрямую.

## Фаза 1. Пользователи (feature-auth)
Точка входа: без пользователя ничего не работает — все данные привязаны к `userId`.
- [x] `domain`: `UserRepository` (порт), `UserMaxRepository` (порт), модели пользователя и базовых максимумов, enum-ы (UserRole, Gender, WeightUnit, HeightUnit, MeasurementUnit).
- [ ] `domain`: заменить разовые максимумы на расширяемые личные результаты (`UserRecord`) с набором метрик, включая расчётные результаты и исходные данные формулы.
- [ ] `domain/data`: добавить схемы результата упражнения: обязательные метрики, фиксированные значения, основная метрика и направление сравнения.
- [x] `data`: адаптеры `UserRepositoryImpl`, `UserMaxRepositoryImpl` (реализация портов через DAO из `core/database`) + мапперы + Hilt `@Binds`.
- [ ] `ui`: `UserSelectScreen` (выбор пользователя), `UserEditScreen` (создание/редактирование = "О себе").
- [ ] Навигация: `AuthScreen` в nav_graph.
- [ ] **Результат:** можно зайти, выбрать/создать пользователя, заполнить «О себе» и добавить личные результаты по схеме выбранного упражнения.

## Фаза 2. Справочники (feature-exercises + feature-anatomy)
Программы и тренировки ссылаются на упражнения и мышцы. Нужны данные. Модели справочников живут в `feature-exercises/domain` (Exercise) и `feature-anatomy/domain` (Muscle, MuscleGroup).
- [x] `feature-exercises/domain`: модель (Exercise) + enum (ExerciseType) + интерфейс (ExerciseRepository).
- [x] `feature-exercises/data`: `ExerciseRepositoryImpl` + маппер + Hilt `@Binds`.
- [x] `feature-anatomy/domain`: модели (Muscle, MuscleGroup, ExerciseMuscle, MuscleRelationEntry) + enum-ы (MuscleInvolvement, MuscleRelation) + интерфейсы (MuscleRepository, MuscleGroupRepository, ExerciseMuscleRepository, MuscleRelationRepository).
- [x] `feature-anatomy/data`: реализации + мапперы + Hilt `@Binds`.
- [ ] Заполнение БД вшитыми данными (упражнения, мышцы, группы) — JSON-ассеты, импорт при первом запуске.
- [ ] `feature-exercises/ui`: список упражнений, группы мышц, поиск и создание пользовательского упражнения с выбором схемы результата.
- [ ] `feature-exercises/ui`: встроенные упражнения нельзя менять; пользовательские можно редактировать только по описанию, а для другой схемы создавать копию без истории.
- [ ] В будущем добавить выбор упражнений по виду спорта.
- [ ] `feature-anatomy/ui`: атлас, детали мышцы.
- [ ] **Результат:** справочник упражнений и мышц доступен, данные в БД.

## Фаза 3. Программы (feature-programs) — просмотр

- [x] `domain`: интерфейсы репозиториев (ProgramRepository, MicrocycleRepository, MicrocycleDayRepository, ExerciseSetRepository, SetTemplateRepository, ProgramCategoryRepository, ProgramTagRepository, ProgramPrerequisiteRepository), модели (Program, Microcycle, MicrocycleDay, ExerciseSet, SetTemplate, ProgramCategoryEntry, ProgramTag, ProgramPrerequisite), enum-ы (MicrocycleDayType, SetType, WeightType, RepType, PrerequisiteType, ProgramCategory).
- [x] `data`: реализации репозиториев + мапперы + Hilt `@Binds`.
- [ ] Вшитые программы (JSON-ассеты, импорт при первом запуске).
- [ ] Перевести шаблоны подходов на набор целевых метрик упражнения.
- [ ] Реализовать суперсеты из любого количества упражнений.
- [ ] Реализовать дропсеты только для упражнений с дополнительной нагрузкой: формульный режим, ручные значения подходов и режим «по ощущениям».

## Контрольные точки ручной проверки на телефоне

После завершения каждой значимой вертикальной срезки собираем debug APK, устанавливаем его на телефон и вручную проверяем результат. Установка выполняется после законченной группы функционала, а не после каждого отдельного файла.

### Точка 1. Пользователи и вход

Проверяем полный пользовательский сценарий:

- первый запуск без регистрации;
- создание первого профиля;
- переключение между профилями;
- создание, редактирование и удаление дополнительного профиля;
- вкладки «Профиль» и «Максимумы»;
- состояния загрузки, ошибки, повторной загрузки и пустых данных;
- корректное поведение кнопки сохранения и выхода без сохранения.

### Точка 2. Каркас основного приложения

Проверяем главный экран с пятью нижними вкладками и шторкой:

- все пять вкладок открываются и пока показывают заглушки;
- шторка открывается из тулбара;
- пункты шторки открывают заглушки настроек, справки и экрана «О себе»;
- возврат назад работает из каждой заглушки;
- активная нижняя вкладка и выбранный пункт шторки визуально выделяются.

### Точка 3. Готовый feature-модуль

После завершения каждого feature-модуля отдельно подключаем его к предусмотренному месту входа и устанавливаем приложение на телефон:

- модуль доступен из нижней навигации или шторки согласно назначению;
- основной сценарий модуля проходит от точки входа до результата;
- проверяются loading/error/ready и пустое состояние;
- проверяются поворот экрана, повторное открытие и возврат назад;
- соседние вкладки, шторка и ранее готовые модули продолжают работать.

Для MVP контрольные точки модулей идут в таком порядке: программы, текущая тренировка, календарь, отслеживание веса, настройки и справка. Справочники упражнений и анатомии проверяются после появления их пользовательского входа — из программ, тренировки или шторки.

### Точка 4. Финальная интеграционная проверка MVP

Перед завершением MVP устанавливаем одну сборку и проходим приложение от первого запуска до завершённой тренировки:

- создаём пользователя;
- выбираем программу;
- запускаем и завершаем тренировку;
- проверяем календарь, вес, настройки и возврат в профиль;
- повторно открываем приложение после выгрузки из памяти;
- убеждаемся, что локальные данные и навигационное состояние не потерялись.
