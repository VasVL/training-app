# Дизайн приложения TrainingApp

> Этот файл фиксирует задумку приложения и архитектурные договорённости. Обновлять по мере развития.

## О приложении
Android-приложение для занятий силовыми видами спорта. Многомодульный проект на Kotlin + Jetpack. Поддержка нескольких пользователей (тренер + подопечные), программ тренировок, дневника тренировок, календаря, отслеживания веса. В будущем — синхронизация с сетью.

---

## Пользователи и вход

- **Несколько пользователей** в приложении: owner (владелец) + дополнительные (подопечные, если приложение использует тренер).
- **Регистрация/сеть** — вторая фаза. Модель данных готова: `remoteId` (nullable) во всех таблицах.
- **Пользователь по умолчанию** — последний активный (last active). Если в настройках включено "пропускать экран выбора" — заходим сразу.
- **Экран выбора пользователя:** выбрать существующего или создать нового.
- **Экран создания = "О себе"** — один экран в двух режимах (create/edit). Поля: имя, вес, рост, пол, возраст, разовые максимумы (по умолчанию присед/жим/становая, можно добавить ещё). Единицы измерения: вес (kg/lbs), рост (cm/inches).

---

## Основной экран

- **Тулбар:** гамбургер слева (шторка: Настройки, О себе), контекстные действия справа. Шестерёнку не дублировать.
- **Шторка (Navigation Drawer):** Настройки, О себе, (прочее — допишу позже).
- **Bottom navigation:** 5 кнопок. В MVP — зафиксированы. В будущем — настраиваемый набор (пользователь выбирает какие 5 экранов из большего набора).
- **5 разделов:**
  1. Список программ
  2. Создание программы
  3. Текущая тренировка
  4. Календарь
  5. Отслеживание веса

---

## 1. Список программ

- **Табы по категориям** (избранное/пауэрлифтинг/бодибилдинг/...). Категории — не enum, а теги (пользователь может создать свою, например "бег"). Порядок табов — в настройках. ViewPager.
- **Список:** название, короткое описание (1-2 строки), лайк (избранное), автор. Залайканые — вверху.
- **Пагинация:** батчами по 10-20 (Paging 3).
- **Вшитые программы:** `isBuiltin=true`, лежат в БД перманентно, удалить нельзя. Импортируются из JSON-ассетов при первом запуске.
- **Сетевые программы:** подгружаются с бекенда (вторая фаза).
- **Пользовательские программы:** пользователь может удалить.
- **Фильтры по тегам:** иконка фильтра в тулбаре → bottom sheet с чипами тегов + сортировка.
- **Поиск:** иконка лупы в тулбаре → SearchView.
- **Микроциклы и тренировки отдельно:** не только цельные программы, но и отдельные микроциклы и тренировки. Переключатель в списке (программы / микроциклы / тренировки).
- **Тап на программу → экран описания программы.**

## Экран описания программы

- Тулбар: стрелка назад.
- Название, чипы с тегами, описание (элапсится, тапом раскрывается).
- Обязательные поля программы (можно ли пропускать тренировки и т.д.).
- Количество микроциклов.
- **Микроциклы — ViewPager** (вариант 2): один микроцикл на экране, свайпом листаешь, номер (1/8, 2/8). Весь экран скроллится.
- Кнопка "Начать!" — всегда видна (sticky внизу).
- **Несколько программ одновременно:** пользователь может проходить несколько программ параллельно. Каждая программа — отдельный "поток" тренировок в календаре.
- **Подтверждение начала:** диалог — "у вас уже есть активные программы (N)", "тренировки добавятся в календарь", "не выполнены условия" (prerequisites). Не блокирует, а информирует.
- **Prerequisites:** условия прохождения (указан разовый максимум, минимальное число подтягиваний и т.д.). Хранятся в программе.
- Тап на микроцикл → подсписок тренировочных дней и дней отдыха. Тап на тренировочный день → упражнения (подходы/веса/повторения).

## 2. Создание программы

- Список незавершённых программ/микроциклов/тренировок + кнопка добавления.
- Тап на незавершённое → экран редактирования. Тап на "добавить" → экран создания (тот же экран, без id).

### Экран редактирования программы
- Тулбар: стрелка назад.
- Название, описание, теги.
- Добавить/редактировать микроцикл. Вставить из имеющихся. Скопировать микроцикл (deep copy, менять проценты/подходы/повторения, упражнения).
- **adjustmentPercent (процент корректировки разового максимума):** в программе — рекомендуемое значение. Фактическое — задаёт пользователь при старте, хранится в дневнике (workout_logs). Процент рабочего веса для тренировки N считается от `100% + adjustmentPercent` всех таких же тренировок предыдущих микроциклов. У самого пользователя разовый максимум не меняется — это потенциальное увеличение. Пояснение — в отдельном диалоге.
- Кнопка "Создать программу".

### Экран редактирования микроцикла
- Тулбар: стрелка назад. Описание, теги.
- Список дней (тренировочные / дни отдыха). У тренировочных — названия (ноги/плечи/грудь/...).
- Кнопка добавления дня. Вставить имеющуюся тренировку. В дне может быть >1 тренировки.
- Дни можно менять местами. Тап на день → экран редактирования дня.

### Экран редактирования дня (одна тренировка)
- Тулбар: стрелка назад. Описание, теги.
- Список упражнений. Кнопка добавления. Упражнения можно менять местами.
- **Связки:** суперсет (несколько упражнений по очереди по одному подходу) — выделять визуально. Дропсет (с одним весом, потом сбрасываешь и без отдыха снова) — значок, число уменьшений.
- Тап на упражнение → экран редактирования упражнения/суперсета.

### Экран редактирования упражнения
- Тулбар: стрелка назад.
- Выбор упражнения через экран групп мышц. Рекомендуемое время отдыха между подходами.
- По умолчанию один подход. Добавление подходов (копируют значения предыдущего).
- **Вес:** свой вес / кг / фунты / проценты. Если проценты — можно указать от какого упражнения считать (по умолчанию то же). Для подтягиваний с весом — процент от (макс + свой вес).
- **Повторы:** число / процент от макса / RPE / **DURATION** (время под нагрузкой, для статических упражнений).
- Если один подход — можно не указывать (просто отметить, что упражнение есть).

### Экран групп мышц
- Тулбар: стрелка назад. Список групп (спина/грудь/ноги/...), название + картинка. Тап → экран упражнений.

### Экран упражнений для группы мышц
- Тулбар: стрелка назад. Список: картинка, описание, теги (основная/вспомогательная мышца).

## 3. Текущая тренировка

- **Если есть начатая тренировка** (`status=IN_PROGRESS`) — открывается она (продолжить).
- **Если текущая тренировка не начата** — открывается **список тренировок на выбор**: запланированные тренировки из всех активных программ (отмечены программой/микроциклом/датой). Плюс кнопки: начать с нуля (другую программу/микроцикл/тренировку) или стартануть **пустую тренировку** (добавлять упражнения по ходу).
- Несколько активных программ — все их запланированные тренировки в одном списке, с пометкой из какой программы.

### Экран прохождения тренировки
- Тулбар: стрелка назад, название, процент корректировки (можно поменять), меню (посмотреть текущую программу — с отмеченными пройденными).
- Описание тренировки (элапсед). Список упражнений (скроллится вместе). Время на упражнение. Кнопка добавления.
- Добавленное самим — можно удалить. Из программы — нельзя, можно пометить пропущенным.
- Текущее время тренировки. Комментарий пользователя. Технические данные (КПШ, средний вес, тоннаж — считаются).
- Кнопка старт/финиш. Старт — таймер. Финиш — окно завершения → окно результатов (общее время, упражнения + время, технические данные).
- Тап на упражнение → экран выполнения упражнения.

### Экран выполнения упражнения
- Тулбар: стрелка назад, название, процент корректировки, меню.
- Описание (элапсед). Список подходов (вес + повторы).
- **Статусы подходов:** неначатый (белый) / выполненный (зелёный) / неполный (жёлтый) / невыполненный (красный). Неполный — указать фактическое (180/200 кг на 5/6 повторений).
- Кнопка добавления подхода. Удалять только свои. Комментарий к подходу.
- **Таблица истории:** подходы из предыдущих и запланированных тренировок с этим упражнением (горизонтальный скролл).
- **Время выполнения упражнения и отдыха:** фиксировать по событиям. Отмена подхода — время остаётся в логе. Рекомендуемое время отдыха — подсвечивать.

## 4. Календарь

- Календарь с пройденными и запланированными тренировками. Дни — цветами.
- Можно перейти на текущую программу. Посмотреть тренировку в конкретный день.

## 5. Отслеживание веса

- Тулбар: стрелка назад. Текущий вес. График изменений (горизонтальный скролл, масштабирование). Кнопка "внести данные" → экран измерений. Кнопка "дневник питания" → дневник питания.

### Экран измерений веса
- Список дата-вес. Цветовая схема (растёт — краснеет, снижается — зеленеет).

### Экран дневника питания (вторая фаза)
- БЖУ и калорийность за день вверху. История по дням (календарь). Список съеденного, удаление. Кнопка добавить → экран выбора еды.

### Экран выбора еды
- Список еды с калорийностью, БЖУ, картинкой. Поиск. Группировка (мясо/крупы/рыба/...).

## Дополнительные экраны

## Архитектурные договорённости

### Модули (вариант A — подмодули как Gradle-модули)

**Core (общие, отдельные Gradle-модули):**
- `core:common:domain` — `Resource<T>` и другие чистые общие Kotlin-типы
- `core:common:logging` — логирование и расширения Timber
- `core:common:ui` — общие UI-ресурсы
- `core/navigation` — Screen, Navigator (порты навигации)
- `core/database` — Room-база, Entity, DAO, Converters, DatabaseModule (Hilt @Provides для TrainingDatabase и DAO). Общая Room-инфраструктура.
- `core/network` — Retrofit, OkHttp (вторая фаза)

**Features (с префиксом `feature-`, подмодули contract/domain/data/ui — Gradle-модули):**
- `feature-auth` (contract, domain, data, ui) — пользователи, "О себе"
- `feature-programs` (contract, domain, data, ui) — программы, микроциклы, дни
- `feature-workout` (contract, domain, data, ui) — текущая тренировка, выполнение
- `feature-calendar` (contract, domain, ui) — календарь
- `feature-weight` (contract, domain, data, ui) — отслеживание веса
- `feature-nutrition` (contract, domain, data, ui) — дневник питания
- `feature-settings` (contract, domain, ui) — настройки
- `feature-exercises` (contract, domain, data, ui) — список упражнений, поиск, свои
- `feature-anatomy` (contract, domain, data, ui) — анатомический атлас
- `feature-help` (contract, domain, ui) — СРЦ, о приложении

**Зависимости подмодулей одного feature:** ui → domain, data → domain + core/database, contract → core/navigation. domain НЕ → ui, domain НЕ → data.

### Изоляция (Ports & Adapters)
- `domain` фичи не зависит от `domain` другой фичи.
- Внешние зависимости — порты (интерфейсы репозиториев в `domain/repository`), реализации (адаптеры) — в `data`-подмодуле фичи, через DI (Hilt).
- `core/database` — общая Room-инфраструктура: `DatabaseModule` (Hilt) предоставляет `TrainingDatabase` и DAO. Реализации репозиториев живут в `data`-подмодулях фичей, инжектируют DAO, маппят Entity ↔ domain model.
- Домен работает со своими моделями, адаптер (`data`) маппит Entity ↔ domain model.

### Структура БД (одна Room-база, таблицы по доменам)

**Пользователи:**
- `users` (id, remoteId, role, name, weight, height, gender, age, weightUnit, heightUnit, isDefault, createdAt)
- `user_maxes` (id, userId, exerciseId, maxValue, unit, measuredAt) — единица: KG/LBS/REPS/SECONDS/METERS/...

**Справочники:**
- `muscle_groups`, `muscles` (groupId, name, description, imageUrl), `exercises` (type: DYNAMIC/STATIC, isBuiltin, createdByUserId), `exercise_muscles` (involvement: PRIMARY/SECONDARY)
- `muscle_relations` (muscleId, relatedMuscleId, relation: ANTAGONIST/SYNERGIST) — связи мышц для анатомического атласа (антагонисты и синергисты)

**Программы:**
- `programs` (без type enum — категории через теги, isBuiltin, isFavorite, recommendedAdjustmentPercent, canSkipWorkouts)
- `program_categories` (вшитые категории-теги, enum ProgramCategory: POWERLIFTING/BODYBUILDING/...)
- `program_tags` (пользовательские теги-строки)
- `program_prerequisites` (условия прохождения)
- `microcycles` (programId nullable — без isStandalone)
- `microcycle_days` (type: WORKOUT/REST)
- `workout_templates` (в дне может быть >1)
- `exercise_sets` (supersetGroupId, setType: SINGLE/SUPERSET/DROPSET, dropsetReductions, weightType, weightRefExerciseId, repType: FIXED/PERCENT_OF_MAX/RPE/DURATION)
- `set_templates` (отдельные подходы)

**Дневник тренировок:**
- `workout_logs` (userId, programId, status: PLANNED/IN_PROGRESS/COMPLETED/SKIPPED, scheduledDate, startedAt, completedAt, adjustmentPercent — фактический, comment). **Несколько активных программ:** `programId` связывает тренировку с программой; разные `programId` с `status=IN_PROGRESS` = разные активные программы параллельно.
- `workout_log_exercises` (isSkipped, durationSeconds)
- `workout_log_sets` (status: NOT_STARTED/COMPLETED/PARTIAL/FAILED, plannedWeight/Reps, actualWeight/Reps, restTimeSeconds, comment)

**Вес:** `weight_measurements` (userId, weight, measuredAt)

**Питание (вторая фаза):** `food_items`, `food_logs`

### Ключевые решения
- **Локальный + удалённый ID:** `id` (локальный) + `remoteId` (nullable) во всех синхронизируемых таблицах.
- **Каскадное удаление:** `users` → ON DELETE CASCADE на user_maxes, workout_logs, weight_measurements, food_logs.
- **Вшитые данные:** `isBuiltin` на programs, exercises. Вшитые нельзя удалить.
- **Мягкое удаление упражнений:** `isDeleted` на exercises. Пользовательские упражнения помечаются `isDeleted=true` (скрыты из списка, но остаются в БД — программы/дневник не разрушаются). Вшитые (`isBuiltin=true`) удалить нельзя. Периодическая очистка: упражнение с `isDeleted=true` и без ссылок удаляется из БД (логика в адаптере). UI показывает удалённое упражнение с плашкой "удалено" при прохождении программы.
- **Шаблоны vs выполнение:** `*_templates` (в программе) и `workout_log_*` (в дневнике).
- **adjustmentPercent:** в программе — рекомендуемое, в workout_logs — фактическое. Расчёт рабочего веса — от всех таких же тренировок предыдущих микроциклов.
- **Единицы измерения:** вес пользователя (kg/lbs), рост (cm/inches), максимумы (unit enum). В БД храним в одной системе, отображаем по настройкам.

### MVP vs вторая фаза
- **MVP:** основной экран (bottom nav 5 кнопок + шторка справа), пользователи, программы (просмотр + создание), текущая тренировка, календарь, вес, настройки, упражнения, атлас, справка.
- **Основной экран (MVP):** тулбар (гамбургер слева → шторка с "Настройки"/"О себе"), bottom navigation из 5 кнопок (список программ, создание программы, текущая тренировка, календарь, отслеживание веса). В MVP набор кнопок зафиксирован; настраиваемость (5 из N) — вторая фаза.
- **Вторая фаза:** сеть/синхронизация, дневник питания, настраиваемая навигация, рейтинги/комментарии программ.
