# Визуальный стиль TrainingApp

> Единые визуальные правила для всех экранов приложения.
> Решения конкретных экранов хранятся в `UI_DESIGN.md` соответствующей feature-фичи.

## Назначение

Интерфейс TrainingApp должен быть спокойным, контрастным и практичным:
тренировочные данные и действия пользователя важнее декоративных элементов.

## Темы

- Базовая тема приложения — графитовая: нейтральные тёмно-серые поверхности и светлый текст.
- Графитовая тема используется по умолчанию.
- Приложение должно поддерживать несколько выбираемых пользователем тем.
- Переключатель темы реализуется в `feature-settings` отдельной фазой.
- Все темы используют Material Design 2 без Material You и динамических цветов.
- Цветовые значения определяются только в XML-ресурсах темы, а не в Kotlin-коде.
- Семантические цвета обязательны для каждого варианта темы:
  - основной;
  - акцентный;
  - фон;
  - поверхность;
  - основной и вспомогательный текст;
  - успех;
  - предупреждение;
  - ошибка.

## Контраст и доступность

- Контраст текста и фона соответствует WCAG AA.
- Цвет не является единственным носителем смысла: статусы и действия сопровождаются текстом, иконкой или формой.
- Минимальная область касания интерактивного элемента — 48 dp.
- У значимых иконок есть текстовая подпись или `contentDescription`.
- Ошибки формы показываются рядом с соответствующим полем понятным текстом.

## Отступы и типографика

- Базовая сетка отступов — 8 dp.
- Малый отступ — 4 dp.
- Минимальный отступ между независимыми элементами — 8 dp.
- Стандартный горизонтальный отступ экрана — 16 dp.
- Используется типографика Material 2.
- Заголовок экрана — 20 sp.
- Заголовок секции — 16 sp.
- Основной текст — 16 sp.
- Вспомогательный текст — 14 sp.
- Размер текста не используется как единственный способ обозначить важность: его дополняют иерархия, расстояние и контраст.

## XML-разметки

- UI строится на XML Views и ViewBinding, без DataBinding.
- Для адаптивной компоновки преимущественно используется `ConstraintLayout`.
- Линейные контейнеры допустимы только для простых локальных групп элементов, когда `ConstraintLayout` не даёт преимуществ.
- Размеры и отступы задаются ресурсами `dp` и `sp`; абсолютное позиционирование недопустимо.
- Экраны корректно работают на разных размерах, плотностях и ориентациях экрана.
- Прокручиваемое содержимое получает безопасный нижний отступ, если его могут перекрыть закреплённые элементы.

## Системные области Android

- Приложение поддерживает жестовую и трёхкнопочную системную навигацию Android.
- Режим системной навигации выбирает пользователь в настройках устройства; приложение не пытается его принудительно изменить.
- Все экраны учитывают `WindowInsets`.
- Контент, кнопки и нижние панели не должны пересекаться со статус-баром, вырезами экрана или системной панелью навигации.

## Компоненты Material 2

- Формы: `TextInputLayout` и `TextInputEditText`.
- Основное действие: заполненная `MaterialButton`.
- Вторичное действие: контурная или текстовая `MaterialButton`.
- Опасное действие требует явного подтверждения.
- Списки: `RecyclerView`; карточки применяются только для самостоятельных объектов, которые необходимо визуально отделить.
- Пустое состояние содержит иконку, короткое объяснение и одно главное действие.
- Загрузка не скрывает уже показанные данные.
- Ошибка содержит понятное описание и действие «Повторить», когда повтор возможен.
- Для главного действия списка используется `ExtendedFloatingActionButton` с текстом и иконкой.
- Плавающая кнопка может скрываться при прокрутке вниз и возвращаться при прокрутке вверх, если это не мешает главному сценарию экрана.

## Навигация

- На корневых экранах не показывается стрелка «Назад».
- На вложенных экранах верхняя панель содержит стрелку «Назад» и заголовок.
- Нижняя навигация используется только на корневых разделах приложения.
- Шторка используется только для глобальных действий и не дублирует доступные на текущем экране действия.

## Ресурсы

- Все тексты интерфейса хранятся в `strings.xml`.
- Формулировать действия и сообщения через понятный результат; по возможности избегать частицы «не». Например, использовать «Отменить изменения?» вместо «Не сохранять изменения?».
- Иконки — векторные ресурсы.
- Цвета, размеры, типографика и темы хранятся в ресурсах `res/values`.
- Новые экраны соблюдают этот документ до добавления XML-разметки.
