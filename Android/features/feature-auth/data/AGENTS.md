# Контекст модуля `feature-auth:data`

## Назначение

Android-модуль адаптеров данных фичи пользователей. Он реализует domain-репозитории через Room и предоставляет внешние contract-интерфейсы через узкие адаптеры.

Полная внутренняя структура находится в [`MODULE_STRUCTURE.md`](MODULE_STRUCTURE.md).

## Правила

- `repository/` — реализации интерфейсов из `feature-auth:domain`.
- `provider/` — реализации публичных интерфейсов из `feature-auth:contract`, когда они читают данные auth.
- `mapper/` — преобразования Room-моделей и проекций в модели соответствующего потребителя.
- `di/` — Hilt-модули для связывания интерфейсов с реализациями.
- Запрашивать из DAO только поля, нужные конкретному сценарию.
- Реализации и внутренние мапперы помечать `internal`, если они не нужны другим модулям.
- Не размещать UI, XML-ресурсы и бизнес-логику в data-модуле.
- При изменении структуры обновлять [`MODULE_STRUCTURE.md`](MODULE_STRUCTURE.md).
