# Контекст модуля `core/reference-data`

## О модуле
Модуль `core/reference-data` — доменные модели и порты (интерфейсы) для справочных данных: упражнения, мышцы, группы мышц, связи мышц. Это **ядро Ports & Adapters**: здесь объявлены чистые domain-модели (без Room-аннотаций) и интерфейсы-порты репозиториев. Реализации портов живут в [`core/database`](../database/AGENTS.md) (Room-адаптер) и маппят `Entity` → domain model.

Полное и актуальное описание внутренней структуры модуля находится в файле **[`MODULE_STRUCTURE.md`](MODULE_STRUCTURE.md)**.

- **[`MODULE_STRUCTURE.md`](MODULE_STRUCTURE.md) нужно обновлять после любых изменений в структуре модуля** — добавление/удаление моделей, портов.
- Общие архитектурные/стилистические замечания для всего Android-проекта — в [`Android/AGENTS.md`](../../AGENTS.md).

## Назначение
- **Domain-модели** (`model/`) — чистые Kotlin `data class` без Room-аннотаций. Используются feature-модулями и доменом. Не зависят от БД/сети.
- **Enum-ы моделей** (`model/types/`) — enum-ы, используемые как типы полей domain-моделей. Вынесены в отдельный подпакет для консистентности с `core/database/entity/types/`.
- **Порты репозиториев** (`repository/`) — интерфейсы доступа к справочным данным. Методы: `suspend` для разовых операций, `Flow` для реактивных запросов. Реализации (адаптеры) — в `core/database`, подключаются через Hilt.

## Архитектурные замечания

### Ports & Adapters
- `core/reference-data` объявляет **порты** (интерфейсы репозиториев) и **domain-модели**.
- `core/database` **реализует** эти порты и маппит `Entity` → domain model. Зависимость направлена: `core/database` → `core/reference-data`.
- Feature-модули зависят от `core/reference-data` (порты + модели), но **не** от `core/database`. Реализация порта инжектируется через Hilt по интерфейсу.
- Домен работает только со своими моделями — никаких Room Entity или DTO в `core/reference-data`.

### Конвенции
- Модели — `data class` / `enum class` без аннотаций внешних фреймворков (Room, Retrofit).
- Порты — `interface` с `suspend`/`Flow`-методами. Имена — `<Entity>Repository` (например, `ExerciseRepository`).
- `MuscleRepository.kt` пока пустой — будет заполнен по мере разработки (порт для доступа к мышцам и связям).
